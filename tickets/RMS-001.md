Bash commands can write outside the thread's folders

Sandbox test (session S-7D01, T01): the Write tool was denied outside T01's area, but echo > ../T02-cache-study/probe.txt, sed -i, touch <root>/threads/probe4.txt and rm all got through. The Bash hook does not check where a command writes. Fix options: parse redirects and file arguments of cp/mv/rm/touch/sed -i/tee and check each against the areas; or refuse write-looking commands that name a path outside the areas.
